# Квалифай — сервис умных ИИ-квизов (аналог Marquiz)

## Что это
SaaS: владелец бизнеса описывает свой бизнес текстом → ИИ генерирует квиз → квиз встраивается на сайт → адаптивные вопросы генерируются на лету → каждый лид получает скоринг 0–100, сегмент (hot/warm/cold/junk) и резюме для продаж. Junk-лиды не тарифицируются (антифрод). Полная спецификация — в `docs/spec-mvp-ai-quiz.md`, читай её перед крупными задачами.

## Стек
- **api/** — Node.js 20+, Fastify 5, TypeScript (ESM, NodeNext), pg, zod, JWT-авторизация
- **БД** — PostgreSQL 16, миграции — голые SQL в `db/migrations/`, раннер `npm run migrate`
- **LLM** — агрегатор Polza.ai (OpenAI-совместимый API, https://polza.ai/docs): `fetch` на `{POLZA_BASE_URL}/chat/completions`, структурный вывод `response_format: json_schema (strict)` + плагин `response-healing`. Весь LLM-код — только через `api/src/llm/client.ts` (абстракция провайдера, не размазывать fetch по коду)
- **Очередь** — таблица `jobs` в Postgres + воркер `api/src/worker.ts` (FOR UPDATE SKIP LOCKED)
- Планируются: **widget/** — Preact, бандл < 50 КБ, подключение одним `<script>`; **admin/** — React + Vite + Tailwind

## Команды
```bash
docker compose up -d db     # Postgres локально
cd api && npm install
npm run migrate             # применить db/migrations/*.sql
npm run dev                 # API на :8080 (tsx watch)
npm run worker              # воркер скоринга (отдельный процесс)
npm run build               # tsc → dist/
```
Нужен `api/.env` (см. `api/.env.example`); без валидного `POLZA_API_KEY` ИИ-эндпоинты вернут ошибку, остальное работает.

## Архитектурные правила
1. **Все промпты и JSON-схемы** — в `api/src/llm/prompts.ts`, вызовы — через сервисы в `api/src/services/ai.ts`. Тексты промптов взяты из спеки (раздел 5) — менять только осознанно.
2. **Транскрипт диалога** — один JSONB в `sessions.transcript`: `[{q, a, generated_by, ts}]`. Его целиком передаём в промпты. Не нормализовывать в отдельные таблицы.
3. **`goals_status`** возвращается промптом 2, сохраняется в сессию и передаётся в следующий вызов — так модель не теряет прогресс целей квалификации.
4. **Фолбэк адаптивного режима**: если LLM отвечает > 4 сек или падает — отдаём заранее сгенерированный вопрос из таблицы `questions` (скелет). Посетитель никогда не должен видеть ошибку.
5. **Антифрод**: сначала дешёвые программные проверки (`api/src/services/antifraud.ts`), их флаги идут в LLM-скоринг как контекст. `segment=junk` ⇒ `billable=false`.
6. **Публичный API виджета** (`/api/w/:quizId/*`) — без авторизации, CORS открыт; отдавать наружу минимум данных (не светить business_context целиком).
7. ID моделей — только через env (`LLM_MODEL_FAST`/`LLM_MODEL_SMART`), формат `провайдер/модель` по каталогу polza.ai/models.
8. Тексты для пользователей (ошибки API, UI) — на русском.
