# ТЗ для дизайнера — «Квалифай», сервис умных ИИ-квизов

## 1. О продукте

«Квалифай» — SaaS-конструктор квизов для лидогенерации (конкурент Marquiz). Ключевое отличие: владелец бизнеса описывает бизнес текстом, а ИИ сам собирает квиз, на лету подбирает следующий вопрос под ответы посетителя, оценивает каждый лид (0–100, сегменты hot/warm/cold/junk) и пишет резюме для отдела продаж. Мусорные заявки не тарифицируются.

Продукт состоит из двух независимых интерфейсов:

1. **Виджет** — то, что видит посетитель сайта клиента. Встраивается на чужие сайты, поэтому обязан выглядеть уместно в любом окружении.
2. **Админка** — кабинет владельца бизнеса: создание квиза с ИИ, редактор, лиды, публикация.

Рабочая версия уже свёрстана и живёт в проде — скриншоты всех экранов приложены к ТЗ (папка `shots/`). Их можно использовать как структурную основу (что где стоит и какие данные показываем), но визуально ждём авторский, более сильный дизайн, а не обводку текущего.

Полная продуктовая спецификация: `docs/spec-mvp-ai-quiz.md` (разделы 1, 4 — обязательно к прочтению).

## 2. Объём работ (что проектируем)

### A. Виджет (мобайл-фёрст, приоритет №1)

Один сценарий из 5 экранов + системные состояния. Карточка квиза: max-width 560 px на десктопе, фуллскрин на мобильном (в режиме попапа).

| # | Экран | Содержимое и требования |
|---|---|---|
| 1 | **Обложка** | Заголовок квиза, подзаголовок, мета-чипы («N вопросов», «~1 минута», бонус), CTA «Пройти квиз». Должна продавать прохождение за 2 секунды взгляда |
| 2 | **Вопрос** | Прогресс (шаг N из M + бар), кнопка «Назад», заголовок вопроса, варианты. **4 типа ответа:** один вариант (клик = переход дальше), несколько вариантов + кнопка «Далее», свободный текст (textarea), слайдер со значением. Варианты — крупные тач-мишени (min 44 px), состояния hover / выбран |
| 3 | **«ИИ печатает»** | Пауза 1–3 сек, пока ИИ генерирует следующий вопрос. Паттерн «печатает…» из мессенджеров. Отдельные тексты: «Подбираем следующий вопрос», «Готовим персональный результат» |
| 4 | **Форма контактов** | Заголовок-оффер, подзаголовок, плашка бонуса, поля (имя / телефон с маской +7 / email — состав настраивается), чекбокс согласия 152-ФЗ со ссылкой (обязателен, дизайн не должен его прятать), CTA. Ошибки валидации под полями |
| 5 | **Результат** | Персональный текст от ИИ (заголовок + 3–5 предложений), CTA (кнопка-ссылка или «Закрыть»). Момент радости — уместна микроанимация (сейчас конфетти) |
| — | **Состояния** | Загрузка квиза; квиз недоступен; ошибка сети (посетитель никогда не видит «голую» ошибку — дружелюбный текст) |

**Режимы встраивания** (нужны макеты всех трёх):
- **inline** — карточка в потоке страницы;
- **popup** — плавающая кнопка-лаунчер (текст настраивается) → модальное окно с блюром фона; на мобильном модалка = фуллскрин с учётом safe-area;
- **button** — открытие того же попапа по клику на любую кнопку сайта клиента.

Обязательный элемент: ссылка «Сделано на Квалифай» в подвале карточки (на бесплатном тарифе).

### B. Дизайн-темы виджета

Виджет темизируется параметрами: основной цвет, второй цвет градиента, фон, цвет текста, радиус скруглений, шрифт. Нужно:
- спроектировать макет так, чтобы он «выживал» при любой смене этих параметров (тёмный фон, нулевые радиусы, корпоративный красный и т.п.);
- отрисовать **5–6 готовых пресетов** (например: базовый индиго, тёмный, минимальный монохром, тёплый/жёлтый, природный/зелёный, премиум-чёрный с золотом) — они попадут в галерею тем в админке.

### C. Админка (десктоп + мобайл)

| # | Экран | Содержимое |
|---|---|---|
| 1 | **Вход/регистрация** | Переключатель режимов, email+пароль, промо-зона с ценностью продукта. Первое впечатление о бренде |
| 2 | **Онбординг «Создать квиз с ИИ»** | Бриф: большое поле «Опишите бизнес» + цель, география, «хороший лид — это…». Кнопка «Сгенерировать» |
| 3 | **Экран генерации** | 10–20 секунд ожидания. Анимация «ИИ думает» + сменяющиеся статусы («Изучает бизнес…», «Придумывает вопросы…»). Это главный вау-момент продукта — сюда стоит вложиться |
| 4 | **Превью сгенерированного квиза** | Заголовок, список вопросов с вариантами и пометкой «зачем этот вопрос», оффер формы контактов, цели квалификации. CTA: «В редактор» / «Сгенерировать заново» |
| 5 | **Дашборд «Мои квизы»** | Сводка (квизов / опубликовано / лидов / горячих), карточки квизов (название, статус черновик/опубликован, режим ИИ/статичный, дата), CTA «Создать квиз», пустое состояние |
| 6 | **Редактор квиза** | Шапка: редактируемое название, статус, кнопка «Опубликовать». 4 вкладки: **Вопросы** (список карточек вопроса + переключатель режима ИИ/статичный), **Бриф для ИИ** (поля брифа + цели квалификации), **Настройки** (лимит вопросов, CTA-текст, поля формы, оффер), **Публикация** (слаг, прямая ссылка, QR-код, 3 сниппета кода с кнопкой «Копировать») |
| 7 | **Лиды** | Фильтры (квиз, «показать отсеянные»), список лидов: скоринг (визуально — сейчас кольцо), сегмент-бейдж (🔥 hot / warm / cold / junk), контакты, резюме в 2 строки. Пустое состояние |
| 8 | **Карточка лида** (drawer/панель) | Скоринг + сегмент, контакты (клик = звонок/письмо), блок «С чего начать звонок» (фраза от ИИ), резюме для менеджера, флаги антифрода, транскрипт диалога (вопрос → ответ) |
| — | **Системное** | Тосты (успех/ошибка), состояния загрузки (скелетоны приветствуются), пустые состояния всех списков |

## 3. Аудитории и тон

- **Виджет**: посетитель сайта малого бизнеса (стройка, ремонт, авто, красота, образование…), любой возраст, 70 %+ с телефона. Дизайн — дружелюбный, лёгкий, «отвечу за минуту», без корпоративного холода. Виджет живёт на чужих сайтах: яркая индивидуальность — в пресетах тем, а не в жёстко зашитом стиле.
- **Админка**: владелец малого бизнеса или маркетолог. Не дизайнер и не айтишник. Тон — «умный помощник сделал за меня»: технологично (продаём ИИ), но просто. Ощущение современного SaaS уровня Linear / Stripe / Notion, а не «панели управления хостингом».

## 4. Технические ограничения (важно, влияет на макеты)

1. **Вёрстка** — Tailwind CSS 4: цвета/отступы/радиусы/тени должны быть выражены токенами (шкала 4 px), а не произвольными значениями на каждом экране.
2. **Шрифт** — сейчас Manrope Variable (полная кириллица). Можно предложить замену, но: вариативный, с кириллицей, бесплатная лицензия. В виджете кастомный шрифт **не грузим** — системный стек либо шрифт сайта-хозяина; заголовки виджета должны хорошо выглядеть и без фирменного шрифта.
3. **Виджет ≤ 50 КБ** — никаких растровых иллюстраций, лотти-анимаций и видео внутри виджета. Только CSS-эффекты, SVG-иконки, эмодзи. Анимации — CSS (given: transition/keyframes), уважение `prefers-reduced-motion`.
4. **Темизация виджета** — через 6 параметров (см. раздел B). В макетах не должно быть элементов, которые сломаются от смены этих параметров.
5. **Иконки** — единый набор SVG (stroke 2px), передать отдельными файлами или Figma-компонентами.
6. **Брейкпоинты**: 390 (мобайл, база для виджета), 768 (планшет), 1440 (десктоп, база для админки). Виджет проектировать mobile-first.
7. **Юридическое**: чекбокс согласия на обработку ПД (152-ФЗ) в форме контактов обязателен и должен быть читаемым (не 8 px серым по серому).
8. Все тексты интерфейса — на русском; закладывать запас ширины (русские слова длиннее английских на ~20 %).

## 5. Деливераблы

1. **Figma-файл** со всеми экранами из раздела 2 в брейкпоинтах 390 и 1440 (768 — только там, где раскладка реально меняется), auto-layout, именованные слои.
2. **UI-kit / дизайн-система**: палитра (с токенами: primary, surface, text, muted, success, warning, danger…), типографическая шкала, отступы, радиусы, тени, компоненты (кнопки 3–4 вида, поля, чипы, бейджи, табы, карточки, тосты, модалки/дроверы) — каждый со всеми состояниями: default / hover / active / focus / disabled / error.
3. **Пресеты тем виджета** — 5–6 штук: значения шести параметров + скрин обложки и вопроса в каждой теме.
4. **Кликабельный прототип** двух флоу: прохождение квиза (обложка → вопросы → контакты → результат) и «регистрация → бриф → генерация → превью → публикация».
5. **Иконки** — SVG-экспорт.
6. Короткое описание анимаций/микровзаимодействий (что, когда, длительность/изинг) — словами или видеозаписью прототипа, спецификации в After Effects не нужны.

## 6. Критерии приёмки

- [ ] Виджет на 390 px: все 5 экранов + 4 типа вопроса + попап-режим, тач-мишени ≥ 44 px.
- [ ] Виджет переживает смену темы: проверен минимум на светлом и тёмном пресетах.
- [ ] Контраст текста — WCAG AA (4.5:1 для основного текста).
- [ ] Все компоненты UI-kit имеют состояния, включая error/disabled/loading.
- [ ] Пустые состояния и состояния загрузки нарисованы (не «потом»).
- [ ] Экран генерации ИИ — с анимацией ожидания, а не статичный спиннер.
- [ ] Figma отдана с auto-layout, без «отвязанных» текстов и растровых кнопок.

## 7. Референсы

- **Тон и уровень**: Linear, Stripe Dashboard, Notion — для админки.
- **Механика квиза**: Typeform (один вопрос на экран, буквенные варианты A/B/C), Marquiz (конкурент — смотреть, чтобы сделать заметно лучше).
- **Вау-момент генерации**: экраны ожидания в v0.dev / Gamma / Durable («ИИ собирает ваш сайт»).
- Текущая реализация: скриншоты в приложении + живой стенд (дадим доступ).

## 8. Процесс

1. Сначала — **концепт**: обложка + экран вопроса виджета и дашборд админки в 1–2 визуальных направлениях. Согласуем направление.
2. Затем полный объём по разделу 2 (виджет → админка → пресеты).
3. Итерации: до 2 раундов правок на блок.
4. Вопросы по продукту — в любой момент, лучше пакетами.

*Контекст для смет: работающий фронтенд уже есть, дизайн внедряется поэкранно; поэтому важнее системность (UI-kit, токены), чем количество артбордов.*
