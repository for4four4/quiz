# Спецификация MVP: сервис умных ИИ-квизов (рабочее название — «Квалифай»)

## 1. Позиционирование

**Одна фраза:** «Квиз, который думает: опишите бизнес — ИИ соберёт квиз, задаст умные вопросы, оценит каждый лид и напишет резюме для продаж. Без оплаты за мусорные заявки».

**Стратегия универсальности:** продукт для любых ниш. У Marquiz универсальность держится на библиотеке из 200+ шаблонов — у нас её заменяет ИИ-генерация: модель собирает квиз под любой бизнес по текстовому описанию, поэтому «шаблон» всегда персональный. Публичную галерею примеров (10–15 популярных ниш: стройка, ремонт, недвижимость, авто, мебель, образование, красота, туризм, юруслуги, b2b-услуги) делаем не как шаблоны, а как маркетинговые демо + SEO-страницы «квиз для …» — каждая ведёт в тот же ИИ-онбординг с предзаполненным брифом.

**Ключевые отличия от Marquiz:**
1. Следующий вопрос генерируется на лету по предыдущим ответам (а не статичное дерево ветвлений).
2. Каждый лид приходит со скорингом и резюме для отдела продаж.
3. Персональный результат / мини-КП в конце квиза вместо страницы «спасибо».
4. Антифрод: невалидные и мусорные заявки не тарифицируются.
5. Плоская подписка без оплаты за заявку, White Label включён во все платные тарифы.

## 2. Архитектура и стек

Принцип: минимум движущихся частей, всё разворачивается одним человеком.

| Слой | Выбор | Почему |
|---|---|---|
| Фронтенд админки | React + Vite, Tailwind | Быстро генерируется Claude, легко поддерживать |
| Виджет для сайтов клиентов | Отдельный лёгкий бандл (vanilla JS или Preact, < 50 КБ), подключается одним `<script>` | Нельзя тащить тяжёлый React на чужие сайты |
| Бэкенд | Node.js (Fastify) или Python (FastAPI) — что ближе вам | Один сервис: API + вызовы Claude |
| БД | PostgreSQL (управляемый в РФ-облаке: Yandex Cloud / Selectel / Timeweb) | 152-ФЗ: персональные данные — на серверах в РФ |
| Очередь фоновых задач | Простая таблица `jobs` в Postgres + воркер (на MVP хватит) | Скоринг и генерация результата идут асинхронно |
| LLM | Claude API: Haiku для рантайма квиза (скорость+цена), Sonnet для генерации квиза в редакторе | Экономика: адаптивный вопрос на Haiku — доли рубля |
| Платежи | ЮKassa (подписки, рекуррент) | Стандарт для RU SaaS, чеки 54-ФЗ |
| Хостинг | VPS/облако в РФ + CDN для виджета | Виджет должен грузиться быстро из РФ |

**Замечание про Claude API из РФ:** прямой доступ к api.anthropic.com из России может требовать зарубежного юрлица/посредника или прокси-агрегатора моделей. Заложите это в план: либо оплата через реселлера API, либо архитектура с абстракцией провайдера LLM (чтобы при необходимости переключиться на другую модель без переписывания кода). В коде — один модуль `llm.ts` с интерфейсом `generate(prompt, schema)`.

## 3. Модель данных

```sql
-- Аккаунты и биллинг
users(id, email, password_hash, created_at)
workspaces(id, owner_user_id, name, plan, plan_expires_at, created_at)
subscriptions(id, workspace_id, provider, status, next_charge_at, amount)

-- Квизы
quizzes(
  id, workspace_id, title, status,            -- draft | published | archived
  mode,                                        -- 'static' | 'adaptive'
  business_context JSONB,                      -- описание бизнеса, оффер, ЦА, цель (сырьё для промптов)
  design JSONB,                                -- цвета, шрифт, лого, скругления
  settings JSONB,                              -- макс. число вопросов, поля контактов, бонус, редирект
  result_template JSONB,                       -- как строить персональный результат
  created_at, updated_at
)

questions(                                     -- только для static-режима и как "скелет" adaptive
  id, quiz_id, position, type,                 -- single | multi | image | slider | text | date
  title, options JSONB, required BOOL,
  branch_rules JSONB                           -- простое ветвление для static
)

-- Прохождения
sessions(
  id, quiz_id, visitor_id, utm JSONB,
  started_at, finished_at, status,             -- in_progress | completed | abandoned
  transcript JSONB                             -- [{q, a, generated_by, ts}, ...] — вся история диалога
)

leads(
  id, session_id, quiz_id, workspace_id,
  name, phone, email,
  score INT,                                   -- 0–100
  segment TEXT,                                -- hot | warm | cold | junk
  summary TEXT,                                -- резюме для продавца (генерирует Claude)
  fraud_flags JSONB,                           -- ['invalid_phone', 'gibberish_answers', ...]
  billable BOOL,                               -- false для junk — не считаем в статистике "лидов"
  crm_sync_status, created_at
)

-- Интеграции и события
integrations(id, workspace_id, type, config JSONB)   -- amocrm | bitrix24 | telegram | webhook | email
events(id, quiz_id, session_id, type, payload JSONB, ts)  -- view, start, answer, drop, lead
```

Ключевое решение: `sessions.transcript` хранит весь диалог в одном JSONB — его целиком передаём в промпты (адаптивный вопрос, скоринг, результат). Никакой сложной реляционки для ответов на MVP не нужно.

## 4. Экраны

### Админка (React SPA)
1. **Онбординг / «Создать квиз с ИИ»** — одно большое поле: «Опишите ваш бизнес и что вы продаёте» + 3 уточнения (цель квиза, город/гео, что считаете хорошим лидом). Кнопка «Сгенерировать» → превью квиза за ~15 секунд. Это первый «вау-момент», он должен случиться в первые 2 минуты после регистрации.
2. **Редактор квиза** — слева список вопросов (drag&drop), справа live-превью в рамке телефона. Переключатель режима: «Статичный» / «Адаптивный (ИИ)». Для адаптивного — редактируются не вопросы, а *бриф*: цель, обязательные факты, которые надо выяснить, тон, лимит вопросов.
3. **Дизайн** — тема: цвета, лого, шрифт, фон. 5–6 готовых пресетов, без глубокой кастомизации на MVP.
4. **Публикация** — код для вставки (`<script>` + попап/встроенный/кнопка), ссылка на отдельную страницу `quiz.вашдомен.ru/slug`, QR-код.
5. **Лиды** — таблица: контакт, скоринг (цветной бейдж), сегмент, резюме, транскрипт по клику, статус синка с CRM. Фильтр «показать отсеянные (junk)» — выключен по умолчанию, но доступен: это доказательство честности антифрода.
6. **Аналитика** — воронка по вопросам (просмотры → старт → каждый шаг → лид), конверсия, средний скоринг по источникам UTM. Блок «Советы ИИ» (см. промпт 5) — одна кнопка «Проанализировать воронку».
7. **Интеграции** — amoCRM, Битрикс24 (OAuth), Telegram-бот для мгновенных уведомлений о горячих лидах, универсальный webhook, email.
8. **Тариф и оплата** — ЮKassa, автопродление, счёт для юрлиц (реквизиты → PDF-счёт; без этого B2B в РФ не продать).

### Виджет (то, что видит посетитель)
- Один вопрос на экран, прогресс-бар, «назад», мобайл-фёрст.
- В адаптивном режиме между вопросами — короткая «печатающаяся» пауза (модель генерирует следующий вопрос ~1–2 сек на Haiku; UX-паттерн чата скрывает задержку).
- Форма контактов с масками, проверкой телефона по формату и (пост-MVP) верификацией звонком/SMS.
- Экран результата: персональный текст + CTA (кнопка «Получить расчёт», мессенджер, телефон).
- Подвал: согласие на обработку ПД (чекбокс, ссылка на политику клиента) — обязательное требование 152-ФЗ и защита от репутации «спам-ловушки».

## 5. Промпты для Claude API

Все рантайм-вызовы — со structured output (JSON), температура низкая, Haiku. Генерация квиза в редакторе — Sonnet. Ниже — готовые системные промпты (адаптируйте плейсхолдеры `{{...}}`).

### Промпт 1. Генерация квиза по описанию бизнеса (редактор)

```
Ты — маркетолог-квизолог с опытом 500+ квизов для лидогенерации в рунете.
Создай квиз для сбора заявок по брифу ниже.

Правила (нарушение любого = брак):
1. 4–7 вопросов. Первый вопрос — самый лёгкий и вовлекающий, отвечается за 2 секунды.
2. Вопросы — только про ПОТРЕБНОСТИ и ситуацию клиента, НИКОГДА про технические детали,
   в которых клиент не разбирается (не «какой фундамент?», а «какой у вас участок?»).
3. Каждый вопрос имеет 3–6 вариантов ответа + где уместно вариант «Ещё не решил(а)».
4. Формулировки — короткие, разговорные, на «вы», без канцелярита и штампов.
5. Последним объектом верни offer_page: заголовок и подзаголовок для формы контактов,
   с конкретным бонусом за оставленный контакт (из брифа или предложи уместный).
6. Добавь qualification_goals: список из 3–5 фактов, которые квиз должен выяснить,
   чтобы отдел продаж понял ценность лида (бюджет, сроки, готовность, ЛПР и т.п.).

Бриф:
- Бизнес: {{business_description}}
- Цель квиза: {{goal}}
- География: {{geo}}
- Хороший лид — это: {{ideal_lead}}

Ответ — строго JSON по схеме:
{
  "quiz_title": str,
  "questions": [{"title": str, "type": "single|multi|slider|text",
                 "options": [str], "why": str}],
  "offer_page": {"headline": str, "subheadline": str, "bonus": str},
  "qualification_goals": [str]
}
Поле "why" — одна фраза, зачем этот вопрос (показываем владельцу в редакторе).
```

### Промпт 2. Адаптивный следующий вопрос (рантайм, Haiku)

```
Ты ведёшь квалификационный диалог с посетителем сайта вместо статичного квиза.
Твоя задача — за минимум вопросов выяснить факты из списка целей и подвести
человека к форме контактов. Ты дружелюбный консультант, не анкета.

Контекст бизнеса: {{business_context}}
Цели квалификации (что нужно выяснить): {{qualification_goals}}
Уже выяснено (история диалога): {{transcript}}
Задано вопросов: {{asked_count}} из максимум {{max_questions}}

Правила:
1. Если все цели квалификации закрыты ИЛИ достигнут лимит вопросов —
   верни action: "finish".
2. Иначе верни ОДИН следующий вопрос, закрывающий самую важную незакрытую цель.
3. Учитывай предыдущие ответы: не переспрашивай, ссылайся на сказанное
   («Вы упомянули участок 6 соток — ...»).
4. Если последний ответ был свободным текстом — сначала пойми его; если он
   бессмысленный (случайные символы), верни flag: "gibberish" и всё равно
   продолжи вежливо.
5. Вопрос ≤ 15 слов, варианты ≤ 5 слов каждый, 3–5 вариантов,
   разговорный тон, на «вы».

Ответ — строго JSON:
{"action": "ask|finish",
 "question": {"title": str, "type": "single|multi|text", "options": [str]} | null,
 "flag": "gibberish|null",
 "goals_status": {"<цель>": "closed|open", ...}}
```

Инженерная деталь: `goals_status` из ответа сохраняйте в сессию и передавайте в следующий вызов — так модель не «забывает» прогресс, и вы видите в аналитике, какие цели чаще всего не удаётся закрыть.

### Промпт 3. Скоринг лида и резюме для продавца (фоновая задача после отправки контактов)

```
Ты — руководитель отдела продаж. Оцени лид с квиза и подготовь резюме для менеджера.

Бизнес: {{business_context}}
Критерии хорошего лида от владельца: {{ideal_lead}}
Диалог с клиентом: {{transcript}}
Контакты: имя={{name}}, телефон={{phone}}, email={{email}}

Задачи:
1. score 0–100: насколько лид соответствует критериям (бюджет, срочность,
   конкретность потребности, полнота ответов).
2. segment: "hot" (звонить в первый час), "warm", "cold", "junk"
   (бессмысленные ответы, тестовое прохождение, спам).
3. summary: 2–4 предложения для менеджера — что человек хочет, ключевые
   параметры, на что обратить внимание в разговоре. Без воды.
4. first_line: одна фраза, с которой менеджеру стоит начать звонок,
   персонализированная под ответы клиента.
5. junk_reasons: если segment="junk" — список причин.

Ответ — строго JSON:
{"score": int, "segment": str, "summary": str, "first_line": str,
 "junk_reasons": [str]}
```

Плюс до вызова модели — дешёвые программные проверки: формат и код оператора телефона, одноразовые email-домены, время прохождения < 8 секунд, повтор IP/fingerprint. Их результат кладите в `fraud_flags` и передавайте модели как дополнительный контекст.

### Промпт 4. Персональный результат / мини-КП (рантайм, показывается посетителю)

```
Ты пишешь персональный результат квиза для посетителя. Это НЕ реклама,
а полезная выжимка, из-за которой человек рад, что оставил контакты.

Бизнес и оффер: {{business_context}}
Диалог: {{transcript}}
Шаблон результата от владельца (если есть): {{result_template}}

Правила:
1. 3–5 предложений: отрази 2–3 конкретных ответа клиента («под ваш участок
   6 соток и бюджет до 5 млн...»), дай предварительную рекомендацию/вилку/
   следующий шаг.
2. Никаких выдуманных цен и обещаний, которых нет в контексте бизнеса.
   Если данных для цифр нет — говори вилками из {{business_context}} или без цифр.
3. Тон — эксперт, который уже начал работать над задачей клиента.
4. Заверши фразой-мостиком к CTA: {{cta_text}}.

Ответ — строго JSON: {"headline": str, "body": str}
```

### Промпт 5. ИИ-аналитик воронки (кнопка в аналитике, раз в день/по запросу, Sonnet)

```
Ты — CRO-аналитик. Проанализируй воронку квиза и дай рекомендации.

Квиз (вопросы и цели): {{quiz_snapshot}}
Статистика за период: {{funnel_stats}}
  формат: [{step, views, drop_rate}], конверсия в лид, ср. скоринг, топ UTM.
Примеры 10 последних транскриптов (обезличенные): {{sample_transcripts}}

Верни JSON:
{"insights": [ {"finding": str, "evidence": str, "severity": "high|med|low"} ],
 "experiments": [ {"hypothesis": str, "change": str,
                   "variant_question": {...} | null} ]}
Максимум 3 инсайта и 2 эксперимента. Каждый инсайт опирается на цифры
из статистики, а не на общие слова.
```

`variant_question` из ответа — готовый вариант для A/B-теста в один клик (пост-MVP).

## 6. Тарифы (draft)

Против per-lead модели Marquiz — плоская подписка, безлимит заявок, White Label везде:

| Тариф | Цена | Что входит |
|---|---|---|
| Бесплатный | 0 ₽ | 1 квиз, статичный режим, 20 лидов/мес, брендинг сервиса |
| Старт | 990 ₽/мес | 3 квиза, адаптивный ИИ-режим, скоринг, безлимит лидов, White Label |
| Про | 2 490 ₽/мес | Безлимит квизов, персональные результаты, интеграции CRM, ИИ-аналитик |
| Агентский | 4 990 ₽/мес | Мультипроекты, доступы команде, приоритетная поддержка |

Юнит-экономика ИИ: адаптивный квиз из 6 вопросов + скоринг + результат ≈ 8–10 вызовов Haiku и 1–2 Sonnet ≈ единицы рублей за лид. При «Про» за 2490 ₽ даже 500 лидов/мес оставляют маржу > 80%. «Безлимит» безопасен, но в оферту заложите fair use (порог, после которого связываетесь с клиентом).

Скидка 15–20% за оплату года. Для агентств — партнёрка 20–25% рекуррентно.

## 7. План по неделям

**Неделя 1 — скелет.**
Postgres-схема, регистрация/авторизация, CRUD квизов, статичный виджет (single/multi/слайдер), встраивание script-тегом, сохранение сессий и лидов. Деплой на VPS в РФ, домен, SSL.

**Неделя 2 — ИИ-ядро.**
Модуль `llm` с абстракцией провайдера. Промпт 1 (генерация квиза) в онбординге. Промпт 2 (адаптивный режим) в виджете + хранение `goals_status`. Ручное тестирование генерации на 8–10 разных нишах (стройка, красота, образование, b2b-услуги, авто и т.д.) — цель: промпт 1 должен выдавать пристойный квиз для ЛЮБОГО описания бизнеса без ручной доводки. Это главный тест недели: универсальность продукта = качество этого промпта.

**Неделя 3 — лиды и ценность.**
Программный антифрод + промпт 3 (скоринг, фоновым воркером). Экран «Лиды» с бейджами и резюме. Промпт 4 (персональный результат). Уведомления о лидах в Telegram-бот (это дешёвая замена CRM-интеграций на первое время и любимая фича малого бизнеса).

**Неделя 4 — деньги и вид.**
ЮKassa: подписки, автопродление, чеки; PDF-счета для юрлиц. Дизайн-темы виджета, страница квиза на поддомене. Политика обработки ПД, оферта, чекбокс согласия в виджете. Лендинг сервиса (сделайте его сами на своём же будущем стеке — и вставьте на него собственный квиз: продукт продаёт себя).

**Неделя 5 — запуск.**
Онбординг-полировка (от регистрации до опубликованного квиза < 10 минут). Галерея «квиз для …» на 10–15 ниш: интерактивные демо + SEO-страницы, каждая с кнопкой «Собрать такой для моего бизнеса». 5–10 «дизайн-партнёров» из РАЗНЫХ ниш (важно для универсального продукта: кейсы должны показывать разброс) — искать в TG-чатах маркетологов, таргетологов и владельцев малого бизнеса, давать «Про» бесплатно на 2 месяца за обратную связь и кейс. Пост на vc.ru («Как я сделал ИИ-альтернативу квиз-конструкторам») + Product Radar и каталоги сервисов. Отдельный канал для универсального продукта — фриланс-маркетологи и веб-студии: один такой партнёр приводит десятки клиентских квизов, поэтому партнёрка 20–25% рекуррентно — с первого дня.

**После запуска (месяц 2–3):** интеграции amoCRM/Битрикс24 (OAuth), ИИ-аналитик (промпт 5), A/B-тесты, верификация телефона, реестр отечественного ПО (открывает госсектор и корпоратов, даёт освобождение от НДС на лицензии).

## 8. Метрики успеха MVP

- Time-to-first-quiz < 10 минут; доля регистраций, опубликовавших квиз ≥ 40%.
- Конверсия квиза посетитель→лид у дизайн-партнёров ≥ 10% (бенчмарк отрасли 12–25%).
- Доля junk-лидов, отсеянных антифродом: 5–15% — и ни одной жалобы «мне посчитали мусор».
- 10 платящих клиентов к концу месяца 2 — подтверждение, что ценность продаётся.

## 9. Главные риски и что с ними делать

1. **Доступ к Claude API из РФ и оплата** — абстракция провайдера в коде с первого дня; запасной вариант — API-агрегаторы моделей, работающие с РФ.
2. **Задержка генерации вопроса** — Haiku + стриминг + «печатающийся» UX; фолбэк: если ответ модели > 4 сек, показать заранее сгенерированный запасной вопрос из скелета.
3. **Галлюцинации в результате для посетителя** — жёсткое правило «никаких цифр вне business_context» в промпте 4 + прогон результата через дешёвую проверку-валидатор.
4. **Marquiz скопирует** — у них per-lead модель конфликтует с «безлимитом» (каннибализация выручки), это ваша структурная защита минимум на год.
5. **152-ФЗ** — данные в РФ, согласие в виджете, механизм удаления контакта по запросу субъекта ПД.
6. **Размытое позиционирование универсального продукта** — «конструктор квизов для всех» звучит как «ещё один Marquiz». Лечится тем, что в коммуникации продаём не конструктор, а результат: «умные лиды со скорингом», «квиз за 60 секунд по описанию бизнеса». Универсальность — свойство продукта, но не заголовок лендинга. SEO-страницы «квиз для {ниша}» дают нишевую релевантность в поиске без нишевого продукта.
